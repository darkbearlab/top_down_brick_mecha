# 寫實化與重量感 設計顧問報告

> 範圍：武器設計原則、機體性能（重量感）、敵人戰術的「貼近現實」方向。敵我都適用。
> 本報告**沒有改任何遊戲程式或數值檔**。實驗用的 patch 放在 `tools/sim/out/realism/`（不進 git），數字都來自無頭模擬。
> 日期：2026-11-25；對照的程式版本：`5a5a1e5`（起步 / 轉向後重新加速）。

---

## 0. 結論先講

1. **重量現在幾乎不影響機動。** `computeSpec` 只有「超過腳的負重」才變慢；負重以內，總重 15 的輕機和總重 42 的重機極速、加速、轉身**完全一樣**（只有剛加的起步加速曲線會看 `loadK`）。後座力、被擊退、推進距離、失衡門檻也都**跟自己的重量無關**；只有機體互撞照重量分。
2. **新數值把「機動 = 防禦」拿掉了，結果重機全面佔優。** 子彈快到躲不掉之後，履帶重砲型對騎槍型從舊數值 1 勝 19 敗變成 17 勝 3 敗、對光束型從 6 勝 13 敗變成 15 勝 4 敗。輕機失去了存在理由；單靠「重的變慢」補不回來（實驗見 §6），輕機需要的是**現實中輕裝單位真正的優勢：資訊和角度**（側翼、繞背、斷線）。這一點又牽涉第 3 條。
3. **敵人是全知的。** 不管看不看得到，敵人都知道玩家在哪（流場直接導向玩家位置），迫擊砲看不到也照目標「現在」的位置打。現實戰場最重要的幾件事——觀測、失去接觸、搜索、壓制、交叉火力——都建立在「資訊不完整」上，所以目前這些手段一個都長不出來。
4. **武器的「速度階層」跟現實相反了幾處：** 機砲比機槍慢、加農砲（現實是最快的穿甲彈）只比機槍快一點、還同時帶大範圍爆風（現實裡穿甲和高爆是兩種彈）。迫擊砲飛行時間固定（遠近都 1.7 秒）、沒有最小射程、第一發就準。
5. **射擊和移動完全脫鉤。** 走路、推進、甚至甩上半身都不影響精度（只有晶片「穩定架」有）；機槍彈量和後座在新數值下只是數字，打起來沒有「扛著重武器」的感覺。現實裡這是腳型之間最大的差別（履帶有穩定器、雙足會晃、懸浮會滑）。

最推薦先做的三件事（§5 詳述）：**A1 迫擊砲要有觀測者 + 試射修正**、**M1 重量進入機動公式（極速看負重比、加速 / 轉身 / 推進看慣性）+ 後座 / 擊退除以重量**、**A2 敵人的感知與「最後已知位置」**。

## 1. 現實參照與尺度換算

### 1.1 尺度原則

| 項目 | 遊戲 | 建議對應 | 說明 |
|---|---|---|---|
| 長度 | 機體約 2 格寬 | **1 格 ≈ 2.5 m**（機體寬約 5 m、高 7～9 m） | 跟現實主力戰車寬度同級，方便對照 |
| 機體速度 | 雙足極速 6.5 格/秒 | ≈ 16 m/s ≈ 58 km/h | 跟現實戰車越野極速同級 → 機體速度**不用改** |
| 重量 | 總重 15～44（單位沒定義） | **1 單位 ≈ 1.5 t** → 輕機 22 t、標準 50 t、重機 65 t | 只是為了講得通；要不要在整備畫面顯示「噸」另外決定 |
| 交戰距離 | 13～20 格（新數值） | 現實 30～50 m | 現實戰車交戰 1～3 km，**距離壓縮約 1/30～1/60**，這是俯視角畫面決定的，不可能照抄 |
| 子彈速度 | 機槍 72 格/秒（新數值） | 現實 850 m/s = 340 格/秒 | 速度壓縮約 1/5 |

**縮放原則：不追絕對值，追三件事——**

1. **順序對**：誰比誰快、誰比誰遠、誰比誰重，順序跟現實一致（玩家的直覺會被這個打中）。
2. **飛行時間的「級別」對**：現實裡直射武器的飛行時間是 0.5～2 秒、導引飛彈 5～15 秒、迫擊砲 10～40 秒。遊戲把整個時間軸壓縮，但**三個級別之間的比例**要保住（直射「幾乎即時」、飛彈「看得到在飛、可以反應」、拋射「有時間跑」）。
3. **取捨對**：重 = 威力大 / 彈少 / 慢 / 後座大；快 = 彈多 / 單發小；穿甲 = 快、沒爆風；高爆 = 慢、有爆風。數字可以壓縮，但取捨的方向不能反。

距離被壓縮得比速度多（1/40 vs 1/5），所以**遊戲裡的子彈飛行時間其實比現實「更即時」**——新數值把子彈加倍，方向是對的，不用再加快。

### 1.2 各類武器對照

現實數字是公開資料的典型值（取整數、只為了比較順序和級別）。「遊戲」欄是舊數值 / 新數值（新數值的實彈速度 ×2、射程不變）。

#### 機槍（`mg`）
| | 現實（重機槍 12.7～14.5 mm / 轉管機槍） | 遊戲 |
|---|---|---|
| 射速 | 重機槍 8～10 發/秒；轉管機槍 30～100 發/秒（要 0.3～0.5 秒轉起來） | 14 發/秒（舊）/ **40 發/秒（新）** |
| 初速 | 850～900 m/s | 36 / 72 格/秒 |
| 有效射程 | 1.5～2 km | 21.6 格 |
| 彈藥 | 車載 1000～3000 發；12.7 mm 一百發連彈鏈約 13 kg | 720 / 1200 發 |
| 散布 | 車載固定架 0.5～2 mrad；行進間大很多 | ±60 mrad（固定） |
| 後座 | 單發小、連射累積推力明顯 | 每發 0.05（新數值每秒 2 格/秒²，相對於加速 11 可以忽略） |

- 新數值的 40 發/秒已經是**轉管機槍**的級別。這樣就應該有轉管機槍的特徵：**轉起來的延遲 + 放開後的慣轉**、連射的持續推力。這是「重量感」最便宜的來源之一（§5 M4）。
- 散布 60 mrad 是現實的幾十倍，但俯視角需要看得到彈幕、也需要讓機槍在中距離「掃」而不是「點」，**保留**；寫實的部分改成「站定 vs 行進」的差別（§2.4）。

#### 機砲（`autocannon`）
| | 現實（25～40 mm 機砲） | 遊戲 |
|---|---|---|
| 射速 | 3～10 發/秒（可選單發 / 低速 / 高速） | 6 發/秒 |
| 初速 | 穿甲脫殼彈 1300～1400 m/s；高爆彈 1100 m/s | **32 / 64 格/秒（比機槍慢）** |
| 彈藥 | 300～900 發，每發 0.5～1 kg | 320 發 |
| 特點 | 雙路供彈（穿甲 / 高爆隨時切換） | 純動能、無爆風 |

- **速度順序反了**：現實機砲比機槍快。建議機砲 ≥ 機槍速度（新數值 64 → 80）。
- 「穿甲 / 高爆雙路」是很好的寫實素材，但會增加操作。建議**不做切換**，只在敘述上把機砲定位成「中口徑穿甲」，維持無爆風。

#### 霰彈（`shotgun`）
| | 現實（戰車砲的霰彈 / 集束彈、大口徑霰彈） | 遊戲 |
|---|---|---|
| 射速 | 單發，裝填 4～8 秒（戰車砲）；泵動式 1 秒 | 0.75 秒 |
| 散布 | 數十 mrad，有效 300～500 m | ±220 mrad、射程 9.6 格 |
| 彈丸速度 | 出膛 1100～1400 m/s，但掉速非常快 | 29 / 58 格/秒 |

- 散布大是對的；可以加「**彈丸越飛越慢、越遠傷害越低**」（目前每顆飛滿射程都同傷害）。這跟現實一致，也讓霰彈「近距離才可怕」更明顯。

#### 狙擊（`sniper`）
| | 現實（反器材步槍 / 長管精準砲） | 遊戲 |
|---|---|---|
| 射速 | 栓動 3～5 秒；半自動 1～2 秒 | 1.3 秒 |
| 初速 | 850～1000 m/s | 75 / 150 格/秒（最快） |
| 精度 | 0.3～1 mrad | ±4 mrad |
| 後座 | 大，要架設 | 1.5 |

- 速度、精度的順序都合理。寫實化的重點在「**要站穩才準**」（§2.4）和「**打完要換位置**」（§3 的狙擊手重新定位）。

#### 加農砲 / 迫擊砲 / 榴彈砲（`cannon`、`mortar_l`、`howitzer`）
| | 現實 | 遊戲 |
|---|---|---|
| 戰車砲 105～125 mm | 穿甲彈 1600～1750 m/s（**最快**）、高爆彈 900～1100 m/s；每分 4～10 發；車內 40 發左右，每發約 20 kg；後座要整個砲架吸收 | 40 / 80 格/秒（**比狙擊慢一倍**）、85 傷害 + 爆風 2.2、2.4 秒一發、8 發 |
| 迫擊砲 81～120 mm | 初速 100～320 m/s、高拋、飛行 10～40 秒；有**最小射程**；第一發偏差大，靠觀測修正（試射 → 夾叉 → 效力射）；沒人看到就只能打預先登記的點 | 固定 1.7 秒、26 格、看不到也打、照目標現在位置、第一發就準 |
| 榴彈砲 155 mm | 飛行 20～60 秒、射程數十公里 | 菁英專用，1.05 秒 |

- 加農砲現在是「快 + 高傷害 + 大爆風 + 大擊退」全包，這在現實上是兩種彈。建議二選一：
  - **穿甲版**（建議作為主版本）：速度提高到接近狙擊（新數值 80 → 120），**爆風縮到 0 或 0.8**、單發不變、對建築傷害降低（穿甲彈打穿不炸開）。
  - 若要保留爆風（打掩體、打蟲群），就承認它是「高爆版」，速度維持。
- 迫擊砲：**飛行時間要隨距離變長**（例如 `lobT = 1.0 + 距離 × 0.05`，26 格 ≈ 2.3 秒）、**最小射程**（6 格內打不了）、**第一發偏差、之後修正**、**需要觀測**（§5 A1）。這是整份報告最「寫實又好玩」的一項：它給玩家一個明確的反制（打掉觀測者 / 斷視線 / 一直移動）。

#### 火箭（`rocket`、`rocket_l`、`rocket_arm`）
| | 現實（無導引火箭 / 火箭筒） | 遊戲 |
|---|---|---|
| 速度 | 火箭筒 115～300 m/s；機載火箭 600～700 m/s | 24 → 38（×0.8） |
| 散布 | 5～20 mrad，受風、受發射平台晃動影響大 | ±50 mrad |
| 後座 | **無後座，但有後焰**（後方危險區） | 0 ✓ |

- 無後座是寫實的，**保留**。後焰（背後貼牆射會傷到自己）很寫實但只會懲罰玩家，**不建議**做。
- 火箭的散布應該隨「射擊時自己在動」變大（跟機槍同一套，§2.4）。

#### 導引飛彈（`missile`、`split`）
| | 現實（反戰車導引飛彈） | 遊戲 |
|---|---|---|
| 速度 | 150～300 m/s（約子彈的 1/3～1/5） | 18 → 32（×0.8），約機槍的 1/3 ✓ |
| 導引 | 兩種：**射後不理**（要先鎖定）/ **半自動指令導引**（射手要一直瞄著，期間暴露） | 鎖定後自動追 |
| 反制 | 煙幕斷鎖、主動防護系統攔截、誘餌 | 煙霧彈斷鎖 ✓、劍劈子彈 |

- 速度比例已經寫實。可以考慮的寫實素材：**指令導引型**（射手要持續瞄著、上半身轉得慢 → 跟脈衝光束同一套 `turnK` 機制），是很有個性的「重武器要付出暴露代價」設計，但屬於新武器，優先度低。

#### 垂直飛彈（`vmissile`）
- 對應現實的**頂部攻擊**飛彈 / 遊蕩彈藥：越過掩體、從上方打最薄的頂部裝甲。
- 寫實化的方向：頂部攻擊**無視正面減傷**（目前 `TORSO_MUL` 照方向算，從上面砸下來應該算「頂部」），或對重裝機加成；代價是飛行時間長、可以被看到。優先度中低。

#### 燒夷彈（`napalm`、`napalm_l`）
- 對應現實的燒夷 / 溫壓彈藥。現實中燒夷彈落地會沿地形流、黏附、燒很久，對步兵和軟目標最有效、對裝甲車輛效果有限（主要是燒感測器、進氣口）。
- 遊戲的「燒腳變慢、燒手臂散布變大、燒頭鎖定變慢」**正好就是「燒感測器和外露件」的寫實版本**，很好，保留。

#### 火焰 / 汽油投射器（`flamer`、`fuel`）
| | 現實（車載噴火器） | 遊戲 |
|---|---|---|
| 射程 | 稠化燃料 60～100 m | 火焰 7 格 / 汽油 10 格 |
| 燃料 | 車載約 1000～1800 公升，一秒一噴大約打 60～80 噴 | 26 秒 / 18 秒 |
| 型態 | **液柱拋物線**，會黏、會流、落地繼續燒 | 火焰：扇形穿透；汽油：會飛的一串燃料 ✓ |

- **汽油投射器才是寫實的那把**。火焰噴射器的「扇形、穿透」比較像高溫氣體噴流；如果要寫實化，可以在敘述上把它定位成「短距離高溫噴流（燒切器）」，而不是「噴火器」。數值不用改。
- 寫實的重量素材：**燃料罐是弱點**（背部被打爆會殉爆，跟彈藥架同一套），可以考慮給汽油型。

#### 光束 / 脈衝 / 能量類（`beam`、`pulse`、`saber`、`power`）
現實沒有可直接對應的戰場武器（只有反無人機用的高能雷射）。**可信地處理**的原則：

1. **能量不是彈藥，限制來自「散熱」和「電容」**：目前的能量條（推進和光束共用）已經是電容的概念，很好。可以再把敘述改成「電容 + 散熱」，不需要新系統。
2. **脈衝光束步槍 = 高能雷射的正確類比**：現實雷射要在**同一點照一段時間**才燒穿。目前「照射 0.75 秒、每 0.05 秒一下、甩不快」就是這個。可以再加一條：**持續照在同一個部位傷害逐步上升**（駐留加成），甩開就從頭算。
3. **環境會削弱能量武器**：煙、塵、火海的煙會讓光束散射。目前的煙霧彈只擋視線和鎖定；可以讓**光束穿過煙霧傷害減半**。這是很便宜、很可信的「寫實」規則，也給玩家反制工具。
4. **光束步槍 48 格/秒的「光彈」**：真正的光是即時的。建議敘述上改稱「電漿彈」或「線圈加速彈」（看得到彈體飛，也解釋為什麼吃能量），名稱改不改由你決定；數值不用動。
5. **鏡面裝甲擋能量**：對應現實的反射 / 燒蝕塗層，可信。

#### 近戰（`saber`、`pile`、`lance`）
- **打樁拳**：對應現實的爆破 / 液壓破門工具，傷害來自「火藥一次推出」，跟機體重量無關 → 現在的設計可信。
- **衝擊騎槍 / 衝撞**：現實裡衝撞的破壞力 = **動量 = 質量 × 速度**。目前騎槍傷害只看速度（`dmgK × 相對速度`），**輕機和重機用騎槍一樣痛**；機體互撞（`collideMechs`）倒是有照重量分。建議騎槍傷害也乘上「自己的重量 / 標準重量」（§5 M2）。這是重量感很直接的一項：重機衝撞恐怖、輕機衝撞像戳。
- **光束劍**：沒有現實對應，屬於能量類，照上面的原則處理即可。

#### 盾牌（`shield`）
- 對應現實的附加裝甲板 / 柵欄裝甲 / 防彈盾。重 6（手臂裡最重）、上半身轉速 ×0.72 → 方向已經對。
- 寫實化缺的一塊：**盾的角度**。現實傾斜裝甲靠角度讓穿甲彈跳彈。可以讓「擦邊打到盾」（入射角很斜）的傷害更低、正面垂直打到的更高——但這會讓盾變更強，**不建議**現在做。

## 2. 重量感：現況與落差

### 2.1 目前重量在哪裡起作用

| 項目 | 目前跟重量的關係 | 程式位置 |
|---|---|---|
| 極速 / 加速 | **只有超過腳的負重**（`loadK > 1`）才變慢，最多到 ×0.5 | `parts.js computeSpec` 的 `moveK` |
| 起步加速曲線 | 看 `loadK`（0.5～1.2 越重越慢出力）✓ 剛加的 | `mech.js driveMech` |
| 腳的轉速 | 超重 ×0.8 | `computeSpec` |
| 上半身轉速 | 只有「手臂超重 ×0.7」和盾牌 | `computeSpec` |
| 推進 | 超重 ×0.8；其他跟重量無關 | `computeSpec`、`mech.js boostKOf` |
| 後座 | `m.vx -= f.x × recoil`：**跟自己的重量無關** | `weapons.js fire` |
| 被擊退 | `m.vx += dx × kb`：**跟被打的重量無關** | `mech.js hitMech` |
| 失衡 | 只看腳的種類（雙足 50 / 逆關節 30 / 懸浮 25 / 履帶不會） | `mech.js hitMech / stagger` |
| 機體互撞 | **照重量分推開和傷害** ✓ | `mech.js collideMechs` |
| 騎槍衝撞 | 只看速度 | `mech.js lanceHit` |
| 精度 | 跟移動、重量都無關（晶片「穩定架」例外；手臂超重 ×1.6） | `weapons.js fire` |

### 2.2 量出來的落差

`computeSpec` 實際算出來（scratch 腳本，不改檔）：

| 配裝 | 總重 | 腳 | 負重比 | 極速 | 上半身轉速 |
|---|---|---|---|---|---|
| 逆關節・輕軀幹・劍 + 光束 | 15 | 逆關節 | 0.44 | 7.4 | 6.5 |
| 狙擊型（預設機） | 21 | 逆關節 | 0.62 | 7.4 | 6.5 |
| 騎槍型 | 29 | 逆關節 | 0.85 | **7.4** | 5.0 |
| 突擊型 | 33 | 雙足 | 0.79 | 6.5 | 5.0 |
| 雙足・重軀幹・機砲 ×2 + 加農 + 垂直 | 42 | 雙足 | 1.00 | **6.5** | 3.6 |
| 重砲型 | 39 | 履帶 | 0.63 | 5.0 | 3.6 |

- 同一雙腳，總重 15 和 29 的極速一模一樣；雙足扛 42（剛好滿載）跟扛 20 也一樣快。**「選輕的」除了負重空間以外沒有回報**，「選重的」也沒有代價。
- 唯一的重量代價（超重）是個懸崖：負重比 1.00 → 1.05 才開始掉速。
- 後座：加農砲每發把**任何**機體往後推 4 格/秒（雙足極速的 61%），輕機和重機一樣；新數值的機槍每秒只推 2 格/秒²，比腳的加速（11）小得多 → **連射完全感覺不到**。
- 擊退：加農砲 kb 7，不管打在 22 t 的輕機還是 65 t 的重機，速度變化都一樣。

### 2.3 新數值讓這件事變嚴重

舊數值下，敵人子彈 ×0.55、躲得掉 → 輕機靠走位當防禦，重量的「代價」由「被打中」來付。新數值下子彈躲不掉，機動的防禦價值消失，重量就只剩好處。模擬（20 場、種子 1，A 勝 / B 勝）：

| 對戰（A vs B） | 舊數值 | 新數值 |
|---|---|---|
| 突擊型 vs 狙擊型 | 20 / 0 | 18 / 1 |
| 重砲型（履帶 39） vs 光束型（懸浮 31） | **6 / 13** | **15 / 4** |
| 打樁型 vs 脈衝型（懸浮） | 20 / 0 | 18 / 2 |
| 重砲型 vs 騎槍型（逆關節 29） | **1 / 19** | **17 / 3** |

結論：新數值下「最重、最耐打、最多槍管」就是正解。這跟現實其實**一致**——現實裡輕裝甲車也打不贏主力戰車的正面——現實的解法是輕型單位**不跟重型單位正面對射**：它們負責偵察、側翼、繞背、斷線、呼叫火力。要讓輕機有價值，需要：

1. 重量有機動上的代價（§5 M1），而且**代價出在「慢慢轉、慢慢加速」，不只是極速**；
2. 角度有回報（側面 / 背面的減傷已經有：`TORSO_MUL`，重機轉身慢 → 輕機繞得到）；
3. **敵人不是全知的**（§3、§5 A2）：輕機能脫離接觸、換角度再進來。

### 2.4 射擊和移動的關係（缺的最大一塊）

現實：
- 履帶 / 輪式車輛有**砲塔穩定器**：行進間射擊精度只小幅下降。
- 步行平台（人）走路時精度大幅下降，站定 / 蹲下 / 架設最準。
- 滑行、懸浮平台：沒有地面支撐，後座會把整台推走。
- 重武器（大口徑砲、狙擊）在不穩的平台上要「架穩」才能打。

遊戲裡腳的種類目前只差在速度和失衡門檻，**加上「行進間精度」就能讓腳型有寫實的個性**：

| 腳 | 行進間散布倍率（建議起點） | 後座 | 寫實理由 |
|---|---|---|---|
| 履帶 | ×1.1 | 照重量 | 有穩定器，打得穩，代價是轉身慢 |
| 雙足 | 站定 ×1、全速 ×1.6 | 照重量 | 步行晃動 |
| 逆關節 | 站定 ×1、全速 ×1.9 | 照重量 | 彈跳步態晃更大，換來最快的加速 |
| 懸浮 | 站定 ×1.2、全速 ×1.5 | 照重量 ×1.5（沒有抓地） | 浮著，整台會被推走 |

**注意可玩性**：玩家大部分時間都在走。倍率要從小開始（全速 ×1.3 左右），而且只對「實彈、火箭」有效，光束 / 脈衝不受影響（能量武器沒有後座，這也是它們的可信優勢）。晶片「穩定架」已經是這個方向，正式機制做了之後它的效果要重新定義（例如「行進間倍率減半」）。

### 2.5 上半身轉速

現實戰車砲塔每秒 40°～45°；遊戲標準軀幹 5 rad/s ≈ 286°/s，**快 6 倍**。這不能照抄：滑鼠瞄準需要跟手，慢下來會讓操作變黏、玩家覺得是延遲而不是重量。

建議：**不降極速，加角加速度**（跟腳剛做的起步加速同一個思路）。
- 小角度修正（< 15°）照舊即時；大角度甩槍（180°）要先加速 → 重的上半身甩得慢。
- 角加速度看「手臂 + 背部武器重量」（上半身的轉動慣量），不是只看有沒有超重。
- 效果：重機被繞背時要「慢慢轉過來」，輕機甩槍快——這就是「輕機靠角度」的機械基礎。

### 3.3 會讓遊戲不好玩的「寫實」

- **玩家被壓制**（螢幕效果、精度下降）：寫實但只是懲罰。用「敵人的子彈打爛掩體」表達壓制就夠了（建築已經會壞）。
- **敵人精準到不給喘息**：新數值已經把雜魚的準度拉到 ×0.45 誤差。再加交叉火力、預瞄轉角，玩家要有**更多資訊**（敵人在哪、誰在瞄我）才能應對；寫實的敵人需要寫實的「偵察手段」給玩家（現在玩家頭部 360° 全知，剛好可以撐住）。
- **看不到的陷阱、無預警的砲擊**：一律要有預告（地上的紅圈、雷射、聲音）。
- **敵人撤退導致追逐**：只給精英 / 王牌、只退一小段。

## 5. 修改案

每案都可以單獨做、單獨驗證。所有新規則都建議**先做成開關**（`parts.js BAL` 或 `ai.js AI_TUNE`，預設 = 現在的行為），由 `heavy.js` 打開 → 舊數值和遠征完全不變，`duel.mjs`（突擊型 vs 狙擊型 10 場 seed 1）照 HEAVY_TEST_PLAN 的規則確認舊數值沒動。

驗證用的基本指令：
```
# 新數值基準
node --import ./tools/sim/register.mjs tools/sim/duel.mjs --a 重砲型 --b 騎槍型 --n 20 --seed 1 --patch tools/sim/patches/heavy.mjs --quiet
# 雜魚包
node --import ./tools/sim/register.mjs tools/sim/gauntlet.mjs --a 突擊型 --brain default --n 10 --patch tools/sim/patches/heavy.mjs
```
每次至少跑兩個種子（`--seed 1`、`--seed 2`），20 場的勝場數雜訊大約 ±2～3。

### 數值調整

#### N1　速度階層（新數值限定）
- **改**：`src/heavy.js` 的 `HEAVY` 加一段 `speed`：機砲 `autocannon` / `autocannon_l` 新數值速度 64 → 80（≥ 機槍）。加農砲先做「穿甲版」實驗：速度 80 → 120、`splash` 2.2 → 0.8、`kb` 不變。
- **驗證**：寫實驗 patch（`tools/sim/out/realism/` 下）在 `applyHeavy()` 之後改這兩把；跑 `重砲型 vs 光束型`、`突擊型 vs 狙擊型`、`gauntlet --a 重砲型`。看加農砲的命中率（`summary.json` 的 `hits / fired`）和雜魚包的勝率。加農砲命中率大漲又同時保住爆風 → 就是太強。
- **取捨**：穿甲加農砲打不到掩體後面、對蟲群沒用 → 這正是「穿甲 vs 高爆」的寫實取捨。

#### N2　迫擊砲飛行時間與最小射程（先新數值）
- **改**：`weapons.js lobNapalm`：`T = d.lobT` 改成 `T = (d.lobK ? d.lobT + dl × d.lobK : d.lobT)`（只有有 `lobK` 的武器才變）；`mortar_l` 加 `lobK: 0.03, minRange: 6`。`ai.js` 迫擊砲開火條件 `dist > 5` 改讀 `d.minRange`。
- **驗證**：`duel --b squad:snipers+missile+mortar`；我量到新數值下迫擊砲每場對玩家造成約 52（全部承受 537 的 10%）。改完應該在 30～50 之間（更好躲，但不是沒用）。

### 機制新增

#### M1　重量進入機動公式（全遊戲，`BAL.massMove` 開關）★ 推薦
- **改**：`parts.js computeSpec`：
  - 極速 `vmax × clamp(1 + a × (0.75 − loadK), 1 − b, 1 + b)`（負重比 0.75 = 現在的平均，不變）；
  - 加速、腳轉速、推進 `× clamp(√(30 / total), 0.78, 1.25)`（**絕對重量**決定慣性）；
  - 上半身轉速保留，由 M3 的角加速度處理。
  - 超重的懸崖（`moveK`）保留，疊在上面。
- **為什麼兩個係數**：只用負重比的話，履帶（負重 62）上的重砲型負重比只有 0.63，**反而變快**——我第一版實驗就是這樣（`tools/sim/out/realism/weight.mjs`）。現實裡腳撐不撐得住決定極速，但「重的東西難推動、難轉向」是質量本身的事。
- **驗證**：我做了三個實驗 patch（都在 `tools/sim/out/realism/`，掛在 `mechs.push` 上改每台的 `spec`，不改遊戲檔）：

  | 對戰（A vs B，新數值，20 場） | 新數值 | weight（負重比 ±15%） | weight2（負重比 ±25%） | weight3（負重比極速 + 重量慣性） |
  |---|---|---|---|---|
  | 突擊型 vs 狙擊型 | 18 / 1 | 19 / 1 | 19 / 1 | 18 / 2 |
  | 重砲型 vs 光束型 | 15 / 4 | 14 / 6 | 14 / 6 | 17 / 2 |
  | 打樁型 vs 脈衝型 | 18 / 2 | 20 / 0 | — | 19 / 1 |
  | 重砲型 vs 騎槍型 | 17 / 3 | 14 / 6 | 13 / 7 | **11 / 9** |

  - **結論**：重量進機動之後，**衝刺 / 近戰型的輕機（騎槍型）明顯受益**（3 → 9 勝），**遠程輕機（光束、脈衝、狙擊）幾乎沒有變化**。在子彈躲不掉的世界裡，遠程輕機的問題不是「不夠快」，而是「快沒有用」——要靠 A2（感知）讓速度變成「脫離接觸、換角度」的能力。
  - 所以 M1 的目的是**手感和一致性**，不是平衡修正；係數用 weight3 的範圍即可。
- **再驗證**：做進遊戲後跑 `gauntlet --a 重砲型` 和 `--a 狙擊型`（雜魚也會被這條影響：拿重武器的雜魚變慢）。
- **玩家手感**：在遊戲裡用重砲型 / 狙擊型各走一圈，確認重機沒有「黏」；起步曲線（剛做的）已經處理了大部分，M1 只是把它延伸到全程。

#### M2　後座、擊退、衝撞照重量（全遊戲，`BAL.massImpulse` 開關）★ 推薦
- **改**：
  - `weapons.js fire`：`m.vx -= f.x × d.recoil × k`，`k = clamp(REF / m.spec.total, 0.6, 1.6)`，`REF = 30`；懸浮再 ×1.3（沒有抓地）。
  - `mech.js hitMech`：三處 `m.vx += dx × kb` 都乘 `clamp(REF / m.spec.total, 0.6, 1.6)`。
  - `mech.js lanceHit`：傷害 × `clamp(自己總重 / REF, 0.7, 1.4)`（`dmgMax` 一起乘）。
  - 新數值另外把連射武器的後座稍微加大（機槍 ×2、機砲 ×2），讓「扛著連射」有持續的推力感。
- **驗證**：我試了「只放大後座」（`tools/sim/out/realism/recoil.mjs`：加農 ×1.6、狙擊 ×1.5、霰彈 ×1.3、機砲 / 機槍 ×2）：突擊型 vs 狙擊型 18/2、重砲型 vs 光束型 18/2——**在雜訊內，後座放大不會打壞平衡**，可以放心當手感調整。照重量縮放後要另外看「輕機帶加農砲」：用配裝 JSON（逆關節 + 輕軀幹 + 加農砲）對突擊型跑 20 場，被自己後座推到牆上的撞擊傷害看 `selfDmg`。
- **取捨**：輕機帶重砲會被推得很遠。這是寫實，也是好的取捨，但要確認推出去不會撞牆受傷（`CRASH_SPEED = 6`；加農砲後座 4 × 1.6 = 6.4 會超過 → **夾到 ×1.4**）。

#### M3　上半身角加速度（全遊戲，`BAL.torsoInertia` 開關）
- **改**：`mech.js driveMech` 最後的 `approachAngle(m.torsoYaw, aimYaw, S.turn × …)`：加一個 `m.torsoW`（角速度），每幀往目標加速、角加速度 `S.turnAcc = S.turn × 6 × clamp(√(12 / (armW + backW)), 0.7, 1.3)`；剩下角度小於 0.25 rad 時直接用原本的方式（小修正保持跟手）。
- **驗證**：模擬器裡 AI 的 `onTarget`（瞄準誤差 < 0.14）會受影響 → 看 `fired / hits` 和繞背時被打的部位分布（`takenPart` 的 rear 比例）。手感一定要人實際玩。
- **風險**：玩家覺得延遲。小角度不受影響是底線。

#### M4　行進間散布（新數值先，`BAL.moveSpread`）
- **改**：`weapons.js fire` 的 `spreadK` 再乘 `moveSpreadK(m)`：`1 + (速度 / vmax) × 腳的係數`（履帶 0.1、雙足 0.3、逆關節 0.45、懸浮 0.3 且站定也 ×1.15）；只對 `bullet`、`rocket`。晶片「穩定架」改成「行進間倍率減半、站定傷害 +20%」。
- **驗證**：`duel` 看各腳型的命中率變化；`gauntlet` 看雜魚（大多是雙足 / 逆關節）會不會太弱——新數值已經把雜魚準度拉高，這條剛好可以抵一點。

#### M5　轉管機槍（新數值限定）
- **改**：`weapons.js updateGuns`：`d.spin`（轉起來的秒數）存在 `gun.spin`，按著增加、放開遞減；實際間隔 = `iv / (0.33 + 0.67 × spin)`。`heavy.js` 給 `mg` 加 `spin: 0.3`。
- **驗證**：模擬看機槍每場傷害（`dealtBy.mg`）；AI 的 `burst = 0.8` 秒一陣，轉起來吃掉約 0.15 秒的有效火力 → 每秒傷害降約 15%，如果太弱就把 AI 的 burst 拉長到 1.2 秒（也更像壓制射擊）。

#### M6　失衡門檻照重量（全遊戲）
- **改**：`mech.js hitMech`：`th = legs.stagger × clamp(√(total / 30), 0.8, 1.25)`。
- **驗證**：`summary.json` 的 `staggered` 次數；特別看逆關節 / 懸浮的輕機會不會太常被定住。

#### M7　能量武器的可信弱點（全遊戲，低優先）
- 光束 / 脈衝穿過煙霧傷害 ×0.5（`smokeBlocks` 已經有）；脈衝持續照同一部位遞增（總傷害不變）；霰彈傷害隨距離遞減。各自一個開關、各自驗證。

### AI 行為

#### A1　迫擊砲要有觀測者 + 試射修正（先新數值，`AI_TUNE.spotter`）★ 最推薦
- **規則**：
  1. 迫擊砲只能打「**同一小隊（或 18 格內任何友軍）有人看得到**」的目標；沒人看到就打**最後已知位置**（A2 做之前，先用「最後一次有人看到的位置」，由小隊共享）。
  2. 第一發落點偏差半徑 `err0 = 3.5` 格；同一個觀測持續看著時，每發 ×0.55（約第三發落在 1 格內）；目標移動超過 4 格或觀測中斷就重來。
  3. 落點預告圈（`mark`）照舊。
- **改**：`ai.js` 的 `d.indirect` 分支：先檢查 `spotted(e, player)`（用 `sees` 掃 `enemies` 中同隊的）；`updateGuns` 傳進去的 `aim` 加上偏差（偏差狀態存在 `e.ai.adj`）。`main.js` 不用動（遠征的小隊已經有 `e.squad`）。
- **配套**：A1 做完後再做「偵察無人機」雜魚（`GRUNTS_LOW` 新一筆，沿用旋停機外型、不帶武器、`want` 拉遠、優先停在看得到玩家的高處）；`SQUADS.mortar` 的 `scout` 換成它。
- **驗證**：`duel --b squad:snipers+missile+mortar --n 10 --seed 1/2`，用 battle jsonl 統計 `mortar_l` 對 A 的傷害（我量的基準：新數值每場約 52）；目標 30～45。再跑一場「先殺觀測者」的大腦（`src/brains/` 可以寫，但要放到暫存資料夾）確認殺掉觀測者後迫擊砲傷害掉到 10 以下。
- **對玩法**：迫擊砲從「不知道從哪來的傷害」變成「有人在看我 → 去處理他」。這是寫實和好玩一致的少數例子。

#### A2　感知與最後已知位置（先新數值，`AI_TUNE.memory`）★ 推薦
- **規則**：
  1. 每台記 `e.ai.seen = { x, z, t }`：看得到目標時更新；小隊成員互相共享（取最新的）。
  2. 玩家開火會暴露位置：開火的那一刻，`WAKE_R` 內的小隊都更新 `seen`（聲音）。
  3. 看不到時：移動目標改成 `seen` 的位置（照路線走），瞄準方向**預瞄 `seen` 那邊**；到了還看不到 → 在附近 6 格搜索 4～6 秒 → 回到待命 / 回據點。
  4. 頭部的 `radarLock`（長距鎖定頭）可以看穿牆 = 這台不受限制（保留特色）。
- **改**：`ai.js updateEnemy` 的 `dx / dz` 改成「看得到用真實位置、看不到用 `seen`」；流場 `flowDir` 是導向玩家的，改用 `routeDir(…, seen.x, seen.z)`（王牌已經在用）。`main.js` 的跟丟（`LOSE_R`）可以改成「搜索結束才跟丟」。
- **驗證**：模擬器裡用 `--brainA` 寫一個「打一下就繞到建築另一邊」的大腦（暫存資料夾），比較新舊：被打中的方向分布（從背面 / 側面打到敵人的比例）應該上升；雜魚包的勝率應該上升 5～10 個百分點。
- **風險**：敵人變笨。用「開火暴露位置」和「小隊共享」平衡；搜索時間不要太長。

#### A3　交叉火力選點（新數值）
- **改**：`ai.js pickSpot`：對每個候選點，算「這個點到目標的方位」跟「其他同伴（或他們的射擊位置）到目標的方位」的最小夾角，夾角在 50°～120° 之間 +6 分、< 25° −4 分。
- **驗證**：`gauntlet --a 突擊型`；在 battle jsonl 的 `state` 裡算同一時間兩台雜魚對玩家的夾角分布（新 vs 舊）。勝率掉太多就把加分降到 +3。

#### A4　狙擊手打完就換位置（全遊戲，成本最低）
- **改**：`ai.js` 狙擊分支 `t = true` 時加 `A.spotT = 0`（下一幀重挑位置）；王牌戰術下偏好「6 格內找掩體」那一組候選點。
- **驗證**：`duel --b squad:snipers`，看 `sniper_l` 的每場傷害（應該小降）和玩家打中狙擊兵的次數（應該降）。

#### A5　壓制（敵人被壓制；新數值）
- **規則**：子彈（任何隊伍）從雜魚身邊 1.5 格內掠過 → `e.ai.sup += 每發 power × 0.02`，每秒消退 0.5；`sup > 1` 時：瞄準誤差 ×(1 + sup)、休息 ×(1 + 0.5 sup)、`pickSpot` 偏好看不到「壓制來源」的點。
- **改**：`weapons.js stepBullet` 加一個「近失彈」回呼（或在 `ai.js` 每幀掃 `shots`，跟閃避同一個迴圈）。
- **驗證**：玩家機槍的價值應該上升：`gauntlet --a 支援型`（雙機槍）勝率上升、`--a 狙擊型` 不變。
- **刻意不做**：玩家被壓制。

#### A6　交替掩護、側翼、煙幕、撤退、地雷（P3）
- 交替掩護：小隊同時「往新射擊點移動」的台數 ≤ ⌈n / 2⌉，其他人站定射擊（`pickSpot` 的換點時間錯開）。
- 側翼：小隊裡一台（第一個醒來的那台以外）`want` 不變但選點角度偏移 ±90°；要有預告（例如那台的頭燈換色）。
- 煙幕：`rush` / `ambush` 小隊醒來時，隊裡一台丟一顆煙到自己和玩家中間（用 `devices.js` 的 `smoke`，每隊一次）。
- 撤退：精英 / 王牌軀幹 < 30%，6～10 格內往隊友 / 增援方向退、退完繼續打。
- 地雷：`fortify`（main.js）在守備據點外圈放 1～2 顆**看得到**的地雷（`devices.js` 的 `mine`，隊伍 = 敵方）。

### 哪些只放新數值、哪些全遊戲

| 只放新數值（heavy.js 打開） | 適合全遊戲 |
|---|---|
| N1 速度階層、M4 行進間散布、M5 轉管機槍、A1 觀測者（先）、A2 感知（先）、A3 交叉火力、A5 壓制、A6 | M1 重量機動、M2 後座 / 擊退 / 衝撞、M3 上半身角加速度、M6 失衡門檻、M7 能量弱點、A4 狙擊換位置、N2 迫擊砲飛行時間（迫擊砲目前只在新數值出現） |

理由：舊數值的敵人子彈刻意放慢（×0.55）、雜魚準度較低，整個節奏是「躲子彈」；觀測、感知、壓制這些都是為「躲不掉子彈」的世界設計的，放進舊數值會讓遠征變難而沒有對應的好處。重量相關的機制（M1～M3、M6）則是**手感和一致性**，跟子彈速度無關，兩邊都適用。A1、A2 在新數值驗證好之後，可以考慮帶回遠征（遠征有迷霧，「敵人不是全知」本來就更合理）。

## 6. 取捨與建議

| 衝突 | 寫實 | 可玩 | 建議 |
|---|---|---|---|
| 子彈速度 | 幾乎即時 | 看得到彈道 | 維持新數值 ×2；**不要再加快**（距離已經壓縮得比速度多） |
| 上半身轉速 | 每秒 40° | 跟滑鼠 | 不降極速，只加大角度的角加速度（M3） |
| 散布 | 毫弧度級 | 看得到彈幕、能掃 | 保留大散布，寫實放在「站定 vs 行進」的差別（M4） |
| 迫擊砲 | 10～40 秒、需要觀測 | 1～3 秒、要預告 | 飛行時間壓縮但隨距離變長、加觀測（A1、N2） |
| 敵人感知 | 會失去接觸 | 敵人不能太笨 | 開火暴露位置 + 小隊共享 + 短搜索（A2） |
| 壓制 | 雙方都會被壓制 | 玩家不想被懲罰 | **只有敵人會被壓制**（A5） |
| 重量 | 重的又慢又難轉 | 重機也要好玩 | 夾在 ±25% 內，代價主要出在「起步 / 轉向 / 甩槍」，極速只小幅 |
| 輕機價值 | 偵察、側翼 | 要有明確回報 | 不靠「更快」補，靠 A2 + 背面減傷 + M3（重機轉身慢） |

**整體建議的順序**：
1. **A1 觀測者迫擊砲**（獨立、收益最清楚、玩家馬上感覺得到「寫實」）。
2. **M1 + M2 重量**（同一批改，一個 `BAL` 開關；手感改善，平衡影響在雜訊內，已有實驗佐證）。
3. **A2 感知**（工程量最大，但它是輕機價值、繞背、搜索、預瞄的地基；做完之後 A3、A5、A6 才有意義）。
4. 之後再看 N1、M3、M4、A4、A5。

**不建議**：玩家被壓制、後焰、槍管過熱 / 換彈、現實等級的砲塔轉速、看不到的地雷。

## R4.0 更正第三輪

**第三輪的 C2（「迫擊砲 100% 都是自己看得到才開火」）是錯的，錯在量測工具。** `los.mjs` 只呼叫了 `setLayout`，沒有呼叫 `resetBuildings()`，所以建築根本沒有蓋起來，量到的視線幾乎全部是通的。同一個原因，「隨機 15 格視線被擋 16%」也是錯的，實際是 **77%**。修好工具後重算第三輪的紀錄：當時迫擊砲每一發開火時，自己看得到目標的只有 **4～17%**。

- G2（迫擊砲躲在掩體後）本身還是合理的，效果也量得到（R4.2），只是第三輪拿來支持它的那個數字是錯的。
- 第三輪的「觀測者全滅後開火頻率變高」**是真的**（那個量的是開火紀錄，不受建築影響）。真正的原因比較可能是迫擊砲以前會往目標走，走著走著自己就看得到了；G2 把這一點改掉了。
- 第三輪的其他結論（C1 倒退走、C3 每幀重抽聲音位置、王牌 / artillery 的勝率）用的是遊戲自己的紀錄，不受影響。

## R4.1 結論先講

1. **G1 有效**：邊退邊打的輕機，軀幹中彈算到「背面」的比例從 43～44% 降到 **0～1%**。但還剩一個副作用：雙足、逆關節、懸浮在**橫移**時，腳朝側面、上半身朝前，所以正面打來的子彈有 **35～62%** 被算成「側面」（×0.85，正面是 ×0.6，多吃約 40%）。繞圈射擊是 AI 和玩家最常做的動作。
2. **觀測者測試大致達成**：巡邏兵死後，迫擊砲的開火頻率是活著時的 0.64 / 0.47 / 0.32 倍（3 個種子，有 2 個 < 一半）；全知的對照組是 1.2～1.7 倍。整包裡迫擊砲每場的傷害 24 / 42 / 24（平均 30）。
3. **`lobHitsBuildings` 改變最大的是燒夷彈，不是迫擊砲**（用場地幾何算的）：目標躲在建築後面時，燒夷彈有 **90%** 撞在牆上、榴彈砲 74%、迫擊砲 33%；看得到的目標三種都是 0%。迫擊砲在實戰紀錄裡只有 0～18% 的砲彈撞牆，而且大多撞在**目標附近**的牆上（撞點離射手中位 13～17 格），不是撞在自己旁邊（撞在射手 3 格內的只有 0～7%）；整包迫擊砲傷害開 / 關都是約 30。
4. **正中央的建築對 1 對 1 影響很大**（新數值）：突擊型 vs 狙擊型 40 → **29** / 40、打樁型 vs 脈衝型 40 → **20** / 40；平均交戰時間從 22～25 秒拉長到 40～78 秒，開始出現 120 秒到時間的平手。重砲型對輕機的那兩組幾乎沒變（約 20 / 40）。這等於把新數值下「躲不掉子彈」的對射，變成繞著掩體打的戰鬥，對靠走位吃飯的輕機特別有利。
5. **流場重算是新數值 AI 最大的單項成本**（佔非閒置時間 34%，每模擬秒 12.9 ms，關掉感知時 5.2 ms）。不過換算到遊戲裡，大約是每幀 0.2 ms，**現在還不是問題**；要等到「載具 / 步兵」或「AI 破牆開道」讓流場變多時才會變成問題。

# AI 用武器破壞建築開道：評估

## 現實參照
- **破牆通行**：城鎮戰裡，步兵常在牆上炸洞，從一棟房子穿到下一棟，避開被火力封鎖的街道。戰車和工兵車輛會直接用主砲或推土鏟開路。
- **打掉敵人的掩體**：對躲在建築裡的敵人，用高爆彈、反戰車武器、迫擊砲把建築打垮，比衝進去打划算。
- **能破牆的是大口徑高爆、爆破藥和推進機具**，不是機槍。小口徑可以打穿薄牆，但打不倒結構。

## 這個遊戲現在的狀況
- 建築一格的耐久中位數 266（R4.2）；倒了變成可以走、子彈可以穿的瓦礫（`grid` 變成 `'r'`）。
- AI 的路線（`pathing.js`）把建築當作牆：Dijkstra 流場，牆格不能走，貼牆的格子加成本。
- 機體大約 1.7～1.9 格寬，所以要走得過去，大約需要**連續兩格**倒掉；穿過一棟 2 格厚的建築，要倒 4 格左右。

## 打穿要多久（照 R4.2 的表，現在不分武器的數字）
- 火箭莢艙 1～2 輪、加農砲 4 格約 8 發（約 20 秒）、機槍約 11 秒。
- 照 D3 修正後（機槍 ×0.25、高爆 ×1.5），大約變成：加農砲 4 格 5～6 發（約 12～14 秒）、火箭莢艙 2～3 輪、機槍 40 秒以上（實際上不會用機槍開道）。

## 值不值得
- **值得，但不是現在**。理由：
  1. 現在的地圖（觀戰街區、遠征）繞路的距離通常不長，AI 很少「被迫繞很遠」；開道的收益有限。
  2. D3（建築傷害分武器）沒做之前，任何拿機槍的雜魚都會變成拆樓機，掩體很快就沒了，掩體戰術（G2、`pickSpot` 的掩體選點）會失效。
  3. 它跟**載具和步兵**（下一節）最相關：戰車開道、步兵躲進建築、迫擊砲把樓打垮。單獨給現在的雜魚做，效果看不太出來。

## 做法建議
- **不要把可破壞建築做進所有流場**。建議分成兩層：
  1. **局部判斷（先做，小工作量）**：AI 看不到目標、`flowDist` 比直線距離長很多（例如超過 2 倍且多 15 格以上），而且直線方向上只隔著 1～2 格建築，自己又有「破牆武器」（高爆 / 火箭 / 加農砲 / 打樁）→ 站定朝那面牆開火，倒了就照新的流場走。檢查用 `rayBlock` + `isBuilding`，不用改流場。
  2. **流場加成本（之後，中工作量）**：建築格不再是「牆」，而是「成本很高的可通過格」（例如 10 格的路程成本 + 依那格剩餘耐久加權）。**只給有破牆武器的單位用的那一份流場**（一種，不是每台一份），而且要先做 D2 的版本號，不然每次建築被打一下就要全部重算。
- **跟其他系統的關係**：
  - 迫擊砲 / 榴彈：現在已經會打到建築（`lobHitsBuildings`），可以順便讓 AI「打垮躲在建築後面的玩家的掩體」——這比開道更有戲，也是現實的主要用法。
  - 掩體戰術：開道讓「躲在樓後面」不再絕對安全，要搭配 D3，不然掩體消失太快。
  - 載具：戰車是最自然的破牆者（加農砲、輾過瓦礫）。
  - 步兵：步兵躲在建築裡時，機體把樓打垮 = 寫實又直觀的對策。
- **工作量**：局部判斷 小（`ai.js` 一個分支 + 一個檢查函式）；分武器建築傷害 小（`buildings.js` / `weapons.js` 幾行 + 武器資料一個欄位）；流場加成本 中（`pathing.js` 的 `blocked` 改成成本函式、版本號、多一份流場）。
- **驗證**：做一張「兩邊被一排建築隔開、繞路要 40 格」的測試場地（只放在 `tools/sim/` 的實驗裡），比較有 / 沒有開道時，AI 第一次看到目標的時間和打穿的牆數；觀戰模式看會不會拆光整張圖（記錄每場倒塌的格數）。
- **範圍**：先只放新數值。

# 戰鬥載具和步兵敵人：可行性研究

## 1. 現有架構能怎麼承載

| 需要的東西 | 現有的對應 | 夠不夠 |
|---|---|---|
| 機體本體 | `makeMech`：`spec`（零件算出來）、`parts`（7 個部位）、`legs.type` 有 `tread` / `hover`、雜魚（`grunt`：一條血、不能推進）、菁英（`ELITES[].elite` 覆蓋數值、`body` 自訂外型、`cores` 弱點） | **戰車 / 自走砲幾乎現成**：要塞砲車、巡邏砲車就是「履帶 + 砲塔 + 自訂車身」的菁英；雜魚的砲車、迫擊砲車、砲塔也是履帶 |
| 外型 | `gruntbodies.js`（雜魚的方塊外型，已經有 `TREADS` 底盤）、`ELITES[].body`、`bugs.js`（完全另一套模型和動作）、旋停機 `setupQuad`（藏起原本的模型換成四旋翼）、蟲群 `setupSwarm`（一台 = InstancedMesh 畫一群） | 夠。載具照 `gruntbodies` / `body` 的格式；步兵照 `setupSwarm` 的 InstancedMesh |
| 動畫 | `src/anim.js`、`poseMech`；規則：**動畫只能是畫面**、不能呼叫 `Math.random()`（模擬會跑掉）、模擬器不呼叫 `poseMech` | 載具只需要履帶 / 輪子轉動、砲塔、砲管後座的畫面；步兵用 swarm 那種「每隻自己的小動作」即可，跟 `offStream` 規則一致 |
| 碰撞 | 圓形（`m.r`，履帶 0.95 × 體型）、`collideMechs` 照質量分推開 / 撞擊傷害 | 長方形車身沒有；**用圓形近似可以接受**（戰車的長寬比約 2:1，可以用 1.1～1.2 的半徑） |
| 命中 / 部位 | `hitMech`：方向表（`HIT_TABLE`）、`TORSO_MUL` 照車身方向（`hullFacing`）、雜魚整台一個部位、蟲群單發最多打掉一隻、爆風 ×1.8 | **車身方向已經是「戰車裝甲」的概念**。要加的是「雜魚載具也吃車身方向」（現在 `!m.grunt` 才吃） |
| 重量物理 | `massMove`（雜魚不吃）、`massImpulse`（`spec.mass`）、`impulseK` 夾 0.6～1.4 | 載具要吃（質量很大 → 幾乎推不動）；步兵另外處理（被爆風吹散 = 死） |
| 腳壞了 | `legK`：腳壞了出力剩 0.35（還能慢慢走） | **履帶斷了應該完全不能動，但砲塔照打**：加一個 `immobile` 旗標即可 |
| 失衡 / 推進 | 履帶不會失衡；雜魚不能推進 | 剛好符合載具 |

## 2. 尺度
- 1 格 ≈ 2.5 m，機體約 5 m 寬。
- **步兵**：人寬約 0.5 m = **0.2 格**，身高 1.8 m 大約是機體的大腿高。在俯視角畫面上只是幾個像素。
  - 單兵個別存在的話，子彈判定要 0.1～0.15 格半徑，機槍散布 ±0.06 rad 在 15 格外是 ±0.9 格 → 幾乎打不中。**現實裡機甲對步兵本來就是靠爆風、壓制和輾壓**，所以這不是 bug，是寫實。但每個兵都是一台機體會讓效能和畫面雜訊暴增。
  - **建議用蟲群（swarm）模型：一個「火力組」（4～6 人）= 一台**。單發最多打倒一人（`swarm.per`）、爆風 ×1.8、整組一條血；畫面上 InstancedMesh 畫幾個小人。這套已經寫好，也有效能紀錄（蟲群 16 隻一台）。
  - 看得見嗎：要加一點輔助——小隊腳下一圈派系色的淡光、或在一定距離外畫成一個小圖示；不然在火光、煙霧裡會看不見。
  - **輾壓**：機體走過步兵 = 一次打倒 1～2 人（`collideMechs` 的分支），寫實又直觀；但步兵會躲進建築 → 機體要打垮建築（跟上一節的開道評估接起來）。
- **載具**：輕型輪式車約 2.5 × 6 m（1 × 2.4 格）、戰車約 3.7 × 8 m（1.5 × 3.2 格）→ 跟機體同級，用菁英的體型倍率（`scale`）就能做。
- **直升機**：主旋翼直徑 14 m ≈ 5.6 格，比機體大很多。畫面上會蓋住一大片，而且應該飛在建築上空、很難被直射武器打到。**比例很難兩全**，建議縮成「大型無人機」（旋停機放大 1.5 倍）而不是真正的直升機。

## 3. 載具和機體的差異（要新增的機制）

| 差異 | 現實 | 遊戲裡怎麼做 | 現有 |
|---|---|---|---|
| 轉向 | 履帶原地轉；**輪式要轉彎半徑**（不能原地轉、倒車慢） | 輪式：新腳型 `wheel`，`legYaw` 只能跟著速度轉（角速度上限 = 速度 / 轉彎半徑）；AI 的避牆要考慮轉彎半徑（`steer` 多試幾個角度，不夠就倒車） | 履帶有；輪式**要新做**（中） |
| 砲塔 | 獨立轉、有轉速上限 | 就是上半身 `torsoYaw` + `turn` | 有 |
| 裝甲方向 | 正面厚、側面薄、頂部和後面最薄 | `hullFacing` + `TORSO_MUL`；載具可以用更極端的倍率（正 0.4 / 側 1.0 / 背 1.6） | 有（要讓雜魚也吃） |
| 行進間射擊 | 戰車有穩定器，行進間照樣準；武裝卡車不穩 | 第一輪 M4 的行進間散布（每種腳一個倍率）就能表達 | 未做（M4） |
| 推進 / 失衡 | 不能推進、不會被打翻 | 雜魚本來就不能推進；履帶不會失衡 | 有 |
| 撞擊 / 輾壓 | 戰車撞上機體 = 很大的動量 | `collideMechs` 照質量分；`spec.mass` 給大一點（戰車 50～60 t ≈ 質量 40） | 有 |
| 部位破壞 | 履帶斷了不能動但砲塔能打；砲塔被打壞不能射但能跑；彈藥殉爆 | 用**非雜魚**的部位：`legs` = 履帶（壞了 `immobile`）、`armR` = 主砲、`backL` = 機槍塔、軀幹 = 車身；`cores` 放彈藥艙（後方弱點，像要塞砲車的油箱） | 部位、核心都有；`immobile` 要新加（小） |
| 乘員逃生 / 投降 | 被打壞後乘員棄車 | 不建議（多出很多步兵單位） | — |

## 4. 候選清單

| 候選 | 現實定位 | 在遊戲裡的角色（給玩家的決策） | 需要的新機制 | 要動的檔 | 工作量 | 風險 | 同場數量 |
|---|---|---|---|---|---|---|---|
| **戰車** | 重裝甲、長程直射、正面幾乎打不穿 | **繞側面 / 背後，或打斷履帶再慢慢處理**；正面硬碰很虧 | 雜魚 / 菁英也吃車身方向、`immobile`（履帶斷）、更極端的方向倍率 | `parts.js`（新菁英 / 雜魚 + 外型）、`mech.js`（`hitMech` 的雜魚分支、`legK` / `driveMech` 的 `immobile`）、`gruntbodies.js` | **小～中** | 跟現在的砲車太像 → 要靠「正面很硬、側背很軟」做出差別 | 1～2 |
| **步兵反裝甲組** | 2～4 人、火箭筒 / 導引飛彈、躲在建築和瓦礫裡 | **優先處理躲著的小威脅**：用爆風、輾壓、或把樓打垮；不處理就被側面一發 | swarm 型的步兵外型（小人 InstancedMesh）、躲進建築（站在建築格邊上、建築擋子彈）、被輾壓 | `ai.js`（setupSwarm 的步兵版）、`parts.js`（新雜魚）、`mech.js`（`collideMechs` 的輾壓） | **中** | 太小看不到；躲在建築裡太難打 → 要有標示 | 2～4 組 |
| 前進觀測員（步兵） | 1～2 人、只觀測、引導砲兵 | **迫擊砲的眼睛**：打掉他迫擊砲就瞎了 | 跟反裝甲組同一套外型；沒有武器 | 同上 + `ai.js` 的觀測者判斷（已經有） | 小（做完反裝甲組之後） | 很小 | 1 |
| 偵察無人機 | 小、快、只觀測 | 同上，但在空中（越過建築看） | 旋停機沒有武器的版本 | `parts.js`、`ai.js`（`want` 拉遠、優先停在看得到目標的地方） | **小** | 很小 | 1～2 |
| 自走砲 | 履帶底盤的榴彈砲，遠距離曲射 | 跟迫擊砲車一樣但射程更長、更痛 → **要靠觀測者才能打** | 幾乎沒有（`howitzer` + 履帶 + `indirect`） | `parts.js` | 小 | 跟迫擊砲車重疊 | 1 |
| 步兵戰車 / 裝甲運兵車 | 中裝甲、機砲、**放下步兵** | 打掉載具前要先擋住下車的步兵 | 載具「放下」步兵（跟增援的空投一樣在旁邊生成） | `main.js`（生成）、`ai.js` | 中 | 步兵沒做之前沒意義 | 1 |
| 武裝卡車 | 輪式、輕裝甲、機槍 / 火箭 | 快、脆，**繞路搶側面**；考驗「先打誰」 | 輪式轉向（轉彎半徑）、行進間散布 | `mech.js`（新腳型 `wheel`）、`ai.js`（避牆考慮轉彎半徑） | **中** | 輪式 AI 很容易卡在街區轉角 | 2～3 |
| 攻擊直升機 / 大型無人機 | 空中、火箭 / 飛彈、越過建築 | 打不到的威脅 → **要用飛彈 / 垂直飛彈**，或躲進建築裡 | 飛行（旋停機已經有）、比較高（飛彈才打得到）、建築不擋它的視線 | `ai.js`（旋停機放大）、`weapons.js`（直射子彈打不到高空 → 要定義高度規則） | 中～大 | 「打不到」很容易變成挫折 | 1 |

## 5. 建議先做的兩種

1. **戰車（菁英或雜魚載具），只放新數值 / 重火力測試先做。**
   - 理由：架構幾乎現成（履帶 + 砲塔 + 自訂車身 + 核心弱點都有）；它直接用到前三輪做好的東西——重量、車身方向、繞背——**是驗證「輕機靠角度打重機」最好的對象**；工作量小～中。
   - 要做的：雜魚 / 菁英載具也吃車身方向（極端倍率）、履帶斷 = 不能動、彈藥艙核心在後方。
   - 驗證：模擬裡 突擊型 / 騎槍型 / 光束型 各打一台戰車，看繞背的比例（`hdir.cjs`）和擊殺時間；正面對射時戰車應該贏，有繞背的時候戰車應該輸。觀戰模式放一台在雜魚包裡看畫面。
2. **偵察無人機 → 前進觀測員（步兵），只放新數值。**
   - 理由：迫擊砲的觀測者規則已經做好、也量得到效果（R4.2），但現在砲擊陣地的觀測者是一台普通的巡邏兵。換成「只觀測、不打人」的單位，玩家的決策會非常清楚（「先打那台無人機」）。無人機是旋停機去掉武器，工作量小，也不會碰到步兵尺度的難題。
   - 步兵（反裝甲組、觀測員）用蟲群的做法可行，但要先解決「看得到」和「躲在建築裡」兩件事（中工作量），所以排在無人機之後。
   - 驗證：觀測者測試（`r2-spot-*.mjs`）把巡邏兵換成無人機，看無人機被打下後迫擊砲開火頻率是不是 < 一半；觀戰看無人機會不會一直停在玩家打不到的地方（太挫折就讓它停在 18 格內）。

## 6. 不建議（或要很晚才做）
- **大量單兵**：效能和畫面雜訊都太大；一律用「一台 = 一組」。
- **真實比例的直升機**：會蓋住畫面、打不到 → 縮成大型無人機。
- **乘員棄車、投降、俘虜**：單位數暴增，玩法收益小。
